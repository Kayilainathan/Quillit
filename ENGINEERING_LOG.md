## 1. Product Strategic Rules (Operating Constitution)

These non-negotiable engineering and product governance standards guide all Quillit architecture and release decisions:

1. **PSR-01 — Evaluation Engine First**: The Evaluation & Coaching Engine (`/api/evaluate`, `evaluationRouter.ts`, `evaluationCalibration.ts`, `EvaluationReportView.tsx`) is the core value engine of Quillit. Every release prioritizes scoring integrity, strict human-editor critique depth, latency efficiency, and zero-hallucination grounding over peripheral UI features.
2. **PSR-02 — Single-Source-of-Truth Scoring (Zero Score Jump)**: Users must never see a provisional local score flash and then mutate into a different AI score seconds later. Live evaluations run as an atomic single pass with an editorial progress state, revealing one authoritative scorecard and logging one clean session record. Offline local evaluation runs strictly as a transparent fallback when the API server is genuinely unreachable.
3. **PSR-03 — Report Hierarchy & Vocabulary Weightage Discipline**: Every evaluation report surfaces insights in strict learning priority order:
   1. **Scorecard & Rubric Notes** (highest weightage: clarity, spoken flow, grammar accuracy, cadence, conciseness)
   2. **Pinpointed Grammar Flaws, Error Corrections & Sentence Variations** (exact verbatim quotes -> natural spoken rewrites -> explicit grammar/cadence rules)
   3. **Alternative Vocabulary & Phrasing Upgrades** (lowest weightage: optional polish; plain, natural spoken English is never penalized for avoiding fancy words, and thesaurus-slop buzzwords are programmatically banned).
4. **PSR-04 — Dynamic Model & Thinking Tier Routing**: Model and reasoning budgets scale dynamically per request based on word count, topic/domain rigor, structural complexity, and live rate-limit cooldowns:
   - `gemini-4-hydrogen` (`HIGH` / `MEDIUM` / `LOW`) for deep/substantive/concise drafts
   - `gemini-3.1-flash-lite` (`HIGH` / `MEDIUM` / `LOW`) for ultra-brief entries, gibberish fast-rejection, and zero-stall rate-limit failover
   - Never cap `maxOutputTokens` artificially low on thinking models; never pass deprecated models or invalid thinking levels (`MINIMAL` is never sent to `gemini-4-hydrogen`).
5. **PSR-05 — Verbatim Grounding & Anti-Inflation Guardrails**: Every inline grammar fix, sentence-level pinpointed rewrite, and vocabulary upgrade is verified against the writer's actual draft before reaching the UI. Gibberish, keystroke spam, and ultra-short stubs are structurally capped so scores remain trustworthy.
6. **PSR-06 — Transport & Cloud Sync Resilience**: Firestore runs over forced HTTP long-polling (`experimentalForceLongPolling: true, useFetchStreams: false`) to prevent 10-second WebChannel hangs in sandboxed iframes and strict proxies. All cloud payloads are strictly schema-sanitized against `firestore.rules`.
7. **PSR-07 — Verification Gate Before Release**: No release is complete without:
   - 100% passing unit tests (`npx --yes tsx --test src/utils/*.test.ts firestore.rules.test.ts server/lib/validation.test.ts`)
   - Clean TypeScript/Vite build + ESLint (`compile_applet` + `lint_applet`) + static Pages build (`npm run build:pages`)
   - Real-browser visual & console verification (`playwright-cli`) confirming zero runtime console errors.
8. **PSR-08 — Persistent Workspace & Background Evaluation Continuity**: Switching between primary navigation tabs (`Write`, `Converse`, `Dashboard`, `Calendar`, `Vocabulary`, `Settings`) must NEVER destroy active draft text, live conversations, title/mode/tone context, in-progress AI evaluations, or open coaching reports. `WriteStudio` and `ConverseStudio` remain persistently mounted while away, with quiet background status indicators in the navigation header.
9. **PSR-09 — Dedicated Live Conversation Practice Boundary**: The `Converse` tab exists exclusively for realistic, real-time conversational English practice (1–3 sentence human texting cadence, persona-locked system instructions, zero generic assistant/essay dumps). Turn latency routes through fast Flash Lite tiers (`MINIMAL`/`LOW` with multi-generation failover), while end-of-conversation evaluation plugs cleanly into the core Dynamic Evaluation Engine (`EvaluationReportView`, Vocabulary Mastery promotion, and Dashboard tracking) grading ONLY the learner's own turns.
10. **PSR-10 — Zero-Stall Multi-Generation Gemini Cascade**: No AI operation in Quillit—and especially the core Evaluation Engine (`/api/evaluate`)—may stall or drop to a 500 error because a single model tier is slow, overloaded, or rate-limited. Every AI route cascades immediately (<5ms) across 5 active, non-deprecated Gemini text generations (`gemini-4-hydrogen` → `gemini-3-flash-preview` → `gemini-3.1-flash-lite` → `gemini-2.5-flash` → `gemini-2.5-flash-lite`) with strict per-step `Promise.race` timeouts, per-request failed-model skip sets (never retrying a stalled/cooled model on a second thinking level), 30-minute self-healing skip for `404`/unsupported models, and strict capability guards (never sending `thinkingConfig.thinkingLevel` to Gemini 2.5 models or `MINIMAL` to `gemini-4-hydrogen`). Fast utility routes (`realtime-assist`, `topics`, `pivot`, `categorize-vocab`, `converse`) prioritize Flash Lite / Flash 2.5 Lite first to keep `gemini-4-hydrogen` quota headroom open for Evaluation.
11. **PSR-11 — Conversational Fluency Benchmark & Dynamic Opener Standard**: Live conversation sessions must open with a fresh, non-repeating opening line every time (`POST /api/converse-opening` + local variant rotation + inline `New opener` and `Edit opener` controls before the first reply). Every learner turn captures genuine client-side response timing (`responseTimeMs`, `thinkTimeMs`, `composeTimeMs`, `wordsPerMinute`, `revisionCount`) paired with live zero-extra-latency `inTimeAnalysis` from `POST /api/converse`. On final evaluation (`POST /api/evaluate-conversation`), the entire time-annotated dialogue is graded on a dedicated 100-point 8-parameter **Conversational Fluency Benchmark** (`Context & Coherence 18%`, `Naturalness & Spoken Flow 16%`, `Grammar & Mechanics 16%`, `Tone & Register 14%`, `Responsiveness & Tempo 12%` [60% grounded in real pace-adjusted timing + 40% holistic], `Initiative & Depth 10%`, `Clarity & Conciseness 8%`, `Vocabulary & Phrasing 6%` [lowest weightage]) integrated with the unified 60-point Dashboard rubric and Vocabulary Mastery.
12. **PSR-12 — Living Engineering Governance & Schema Lockstep**: `ENGINEERING_LOG.md` is updated alongside every user-facing feature release, architectural refactor, or resolved production defect. Any new Firestore document field must land simultaneously across `firebase-blueprint.json`, `firestore.rules`, `firestore.rules.test.ts`, and `src/utils/cloudSync.ts` before deployment.
